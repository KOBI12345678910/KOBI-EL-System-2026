# 🏗️ SmartBuild Pilot 2.0 — מגדל בקרה ליזמות נדל"ן

השירות החמישי במונורפו **Techno-Kol Uzi ERP 2026** (פורט **3400**).

מימוש מחדש — משופר, מתקדם וחכם — של מערכת SmartBuildPilot/YzmCon המקורית (Base44, ‏352 ישויות, ‏247 דפים), הפעם כמערכת הנדסית אחת קוהרנטית: **אפס תלויות חיצוניות, מנועים דטרמיניסטיים, הכל נבדק**.

## הרצה

```bash
cd smartbuild-pilot
npm start            # http://localhost:3400 — מגדל הבקרה
npm test             # 30 בדיקות node:test — ללא התקנה כלשהי
```

אין `npm install`. אין תלויות. ‏Node 18+ בלבד.

## ארכיטקטורה

```
                    ┌──────────────────────────────┐
                    │        public/index.html     │  מגדל בקרה RTL (קובץ יחיד)
                    └──────────────┬───────────────┘
                                   │ fetch /api/*
                    ┌──────────────▼───────────────┐
                    │         src/server.js        │  node:http בלבד, 25+ נתיבים
                    └──────────────┬───────────────┘
          ┌────────────────────────┼─────────────────────────┐
┌─────────▼─────────┐   ┌──────────▼──────────┐   ┌──────────▼──────────┐
│     src/core      │   │     src/engines     │   │      src/data       │
│ contracts         │   │ event-bus           │   │ store (in-memory,   │
│ entity-map (26)   │   │ budget │ sales      │   │  audit אוטומטי)     │
│ state-machines(18)│   │ cashflow │ zero     │   │ seed — "מגדלי       │
│ workflow-flows(6) │   │ finance │ risk      │   │  אלמוגים" (600+     │
│ pipeline (14)     │   │ montecarlo │ alerts │   │  רשומות עקביות)     │
│ wiring-spec       │   │ insights │ health   │   └─────────────────────┘
│ orchestrator (21) │   └─────────────────────┘
└───────────────────┘
```

- **core** — מקור אמת יחיד: מפת ישויות, מכונות מצבים, זרימות, צנרת 14 שלבים, ו-Orchestrator שהוא השכבה **היחידה** שמותר לה לשנות מצב עסקי.
- **engines** — 11 מנועים טהורים (ללא I/O, ללא `Date.now()`): אותו קלט → אותו פלט, תמיד.
- **data** — store בזיכרון עם רישום ביקורת אוטומטי על כל שינוי.

## הכללים העסקיים הממומשים

| תחום | כלל |
|------|-----|
| **חוק המכר** | ‏20% ראשונים ממחיר החוזה — ללא הצמדה; כל שקל מעבר — צמוד למדד ב-**50%** מהשינוי בלבד. מיושם בגבייה בפועל, בתחזית התזרים ובלוחות הסילוקין |
| **תקציב** | ‏`revised = approved + transfers + change_orders`, ‏FAC, סטיות, רמת סיכון אוטומטית (‏>15% קריטי) — נוסחאות המפרט המקורי §3.3 |
| **דוח אפס** | GDV, רווח גולמי, מרווח על הכנסה/עלות, נקודת איזון למ"ר, **IRR** (ניוטון-רפסון חודשי→שנתי), **NPV** |
| **תזרים 40 חודשים** | עבר = בפועל; עתיד = תחזית כולל הצמדה צפויה, פריסת יתרות תקציב, ריבית ליווי, **ומכירות עתידיות לפי קצב היסטורי** |
| **קובננטים** | LTV, LTC, כיסוי מכירות מוקדמות, הזרמת הון — מחושבים חיים עם רצועת אזהרה של 10% מהסף |
| **מונטה-קרלו** | ‏2,000 ריצות דטרמיניסטיות (seeded): עלות~N, הכנסה~N, עיכוב~משולש; פלט P5/P50/P95, הסתברות הפסד, VaR95, פירוק רגישות |
| **אישורים מדורגים** | הוראת שינוי: ‏<2% מנהל כספים, ‏<10% CFO, ‏<20% ועדת השקעות, מעל — דירקטוריון |

## במה זה משופר מהמערכת המקורית?

1. **Event-Driven באמת** — כל פעולה עסקית מפרסמת אירוע מוקלד; במקור זה היה מסמך תכנון, כאן זה קוד רץ.
2. **אפס מספרים קשיחים** — כל KPI נגזר מהישויות בזמן הבקשה. שינוי דרך ה-Orchestrator מעדכן מיידית תקציב, תזרים, קובננטים והתראות.
3. **No Dead Pages כ-API** — ‏6 השאלות אינן קונבנציה של UI אלא חוזה שהשרת אוכף (`/api/360`).
4. **שכבה חכמה דטרמיניסטית** — 12 חוקי התראה + 10 היוריסטיקות תובנה עם אומדני ₪ + Next Best Action לכל ישות, בלי תלות במודל חיצוני.
5. **דטרמיניזם מלא** — ‏PRNG זרוע, `asOf` מוזרק, אפס `Date.now()` במנועים → כל חישוב שחזיר ובדיק.
6. **‏30 בדיקות** המכסות את חוק המכר, נוסחאות תקציב, IRR, אינווריאנטות תזרים, שומרי Orchestrator וכל נתיבי ה-API.
7. **אפס תלויות** — ‏1,630 קבצים ו-70+ חבילות npm במקור הפכו ל-~20 קבצים שרצים בכל מקום ש-Node קיים בו.
